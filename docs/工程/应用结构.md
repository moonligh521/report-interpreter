# 应用结构

对齐企业架构规范第 2 节与菜品推荐双模块形态。行为以 1.3 Final 为准。

## 构建

| 项 | 值 |
| --- | --- |
| groupId | `com.moonligh` |
| artifactId | `report-interpreter` |
| version | `0.1.0-SNAPSHOT` |
| packaging | `pom` |
| Java | 21 |
| 依赖版本 | `platform-bom`（不在本仓重复钉 MyBatis 等） |

| 模块 | 职责 | 是否启动 |
| --- | --- | --- |
| `report-interpreter-api` | `*Req` / `*Res` / 枚举契约 jar | 否 |
| `report-interpreter-service` | 控制器、用例、领域、基础设施、启动入口 | 是 |

根目录：`mvn -B verify`。

## 包

```text
com.moonligh.report
├── ReportInterpreterApplication
├── controller/                 # HTTP；不写 SQL，不开事务
├── service/                    # 用例与事务边界
├── domain/                     # 规则与端口（*Store 等）
│   ├── parse/
│   ├── rule/
│   ├── critical/
│   ├── interpret/
│   ├── delivery/
│   └── …
└── infrastructure/
    ├── persistence/            # *Mapper 接口 + 端口实现
    ├── redis/
    ├── mq/
    ├── vector/
    ├── ai/
    ├── ocr/
    └── identity/               # 就诊人归属 HTTP 客户端
```

`src/main/resources/mapper/*.xml` 与 Mapper 接口同属 persistence 落点。

api 模块仅放对外契约类型；service 依赖 api + `platform-*`。

## 返回与鉴权

- 统一 `Result{code,message,data,traceId}`；成功 `code=200`。  
- 浏览器：`/api/report/**`，信网关账号头。  
- 内部：`/internal/report/**`，`X-Internal-Token`。  

## 测试落点

- 领域/验收：不强制起 HTTP；断言状态、错误码、结构化字段。  
- Mapper XML：可用 Testcontainers / H2 策略在实施规格中选定，但正式 SQL 仍在 XML。
