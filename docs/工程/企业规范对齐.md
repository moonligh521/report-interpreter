本仓工程约定**不得自创**。权威与落地参照如下；冲突时按顺序取舍。

| 优先级 | 来源 | 管什么 |
| --- | --- | --- |
| 1 | `moonligh-platform/docs/企业架构规范.md`（副本：`docs/对齐/企业架构规范.md`） | 分层、持久化、Result、错误码、内部令牌、仓边界 |
| 2 | 本仓 `docs/superpowers/specs/2026-11-18-AI报告解读企业级完整方案-design.md` | 报告解读领域规则与分期 |
| 3 | `registration-assistant` 现行 CONTRIBUTING / `docs/工程/*` | 分支命名、中文工程文档结构、基础设施引入规则、网关/身份协作 |
| 4 | `nutritionist` 现行 CONTRIBUTING / V0.1 施工方案 Global Constraints | 禁 Map、Req/Res、幂等、双模块、阶段门禁、Hybrid RAG 同构 |

## 1. 与挂号、菜品推荐共同强制项

| 项 | 约定 |
| --- | --- |
| 运行时 | JDK 21、Spring Boot 4.1.1；版本以 `platform-bom` 为准，业务仓不重复钉死三方大版本 |
| 脚手架 | 只依赖 `platform-*`；禁止依赖 `registration-assistant` / `nutritionist` / `clinical-record` 的业务 jar |
| 协作 | HTTP + 平台内部令牌；病情主数据只读 `clinical-record` |
| 包分层 | `controller` / `service` / `domain` / `infrastructure.persistence`（及 infrastructure 其它适配子包）；领域不依赖 Web/MyBatis |
| 持久化 | SQL **只**在 `src/main/resources/mapper/*.xml`；官方 MyBatis starter；不用 MyBatis-Plus / 自封装 BaseMapper |
| Mapper 扫描 | `@Mapper` + `@MapperScan(..., annotationClass = Mapper.class)`；`mapper-locations=classpath:mapper/**/*.xml`；打开 underscore→camel |
| 事务 | 放在应用 `*Service` |
| 返回 | 平台 `Result`；业务 HTTP 常为 200；**成功 `code=200`**；鉴权/限流/协议错误不得一律假装业务成功 |
| 错误码 | 先写入平台 `ErrorCode` 再引用；本域号段 **41xx**（须合入平台枚举） |
| 鉴权 | 浏览器走网关头（与挂号一致：`X-Account-Id` 等）；内部 `/internal/**` 用 `X-Internal-Token` / `consult.auth` |
| 配置 | 业务根键 `report.*`；鉴权键仍用 `consult.auth` |
| API | 浏览器 `/api/report/**`；内部 `/internal/report/**` |
| 对象化 | **禁止** `Map<String,Object>` 作接口/领域/Mapper 契约；用 record `*Req` / `*Res` / `*Command` / `*Result` / `*Row`；手工映射；无 BeanUtils / MapStruct / Lombok |
| 幂等 | 写接口必须 `Idempotency-Key`（≤64）；同键同哈希回放，同键不同哈希冲突 |
| 时间/数值 | `Instant`；业务日 `LocalDate`+时区；指标值 `BigDecimal`+单位 |
| 日志 | 可写 id/version/trace；**不写**指标全文、病情正文、姓名、证件号 |
| 分支 | `feature-V主.次-年月日[-短英文名]` / `release-…` / `hotfix-…`；禁止 `feat/` |
| 验证 | `mvn -B verify`；默认不连真模型/外网 |
| 代码风格 | 小类小方法、显式分支、必要中文注释；优化靠重构不堆条件 |
| 依赖引入 | 用到再加；端口在 domain，封装在 `infrastructure` 子包（对齐挂号《基础设施》） |

## 2. 与两边差异处的本仓取舍

| 主题 | 挂号 | 菜品推荐 | 本仓 |

## 3. 号段与平台待办

平台 `ErrorCode` 注释现为：`1xxx` 通用、`11xx～13xx` 挂号、`21xx～30xx` 营养、`31xx` 临床。  
本仓业务码 **4101～4110** 必须先合入 `moonligh-platform` 枚举与号段说明，再在本仓引用（foundation 门禁）。

## 4. 对齐检查清单（服务算对齐 iff）

摘自企业架构规范第 9 节，并叠加菜品对象化：

1. 构建 `import` `platform-bom`，MyBatis 版本不在本仓重复声明  
2. 正式 SQL 全在本服务 Mapper XML  
3. 启动类带 `annotationClass=Mapper.class` 的 `@MapperScan`  
4. 事务在应用服务上  
5. 对外/内部返回平台 `Result`，错误码来自平台  
6. `/internal/**` 用平台内部令牌过滤器  
7. 不保存其它服务拥有的主数据；病情只读 clinical-record 快照  
8. 无业务边界 `Map<String,Object>`；写接口有幂等键  
9. 分支名与 `check-branch-name.sh` 一致
