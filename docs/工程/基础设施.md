# 基础设施

对齐 `registration-assistant/docs/工程/基础设施.md`：代码用到哪一项，构建文件就引用哪一项，并在 `infrastructure` 封装。没有调用方的工具不写进依赖，也不预建空包。

系列仓库共用版本；本仓只引用自己已经调用的工具。版本以 `platform-bom` 为准。

## 选定版本

| 能力 | 工具 | 版本 | 本仓库的首次引入时机 |
| --- | --- | --- | --- |
| 应用运行时 | JDK、Spring Boot | JDK 21、Spring Boot 4.1.1（BOM） | foundation |
| 统一返回 / 鉴权 / 观测 | `platform-common` / `security` / `observability` | BOM | foundation |
| 库表迁移 | Flyway | 随 Boot 管理 | parse 起落业务表 |
| 结构化事实 | MySQL | 8.0.46；库名 `report_interpreter` | parse / rules |
| 缓存 / 锁 | Redis + `platform-redis` | 8.2.10 | delivery-gate（SSE 加速等） |
| 事务消息 | RocketMQ + `platform-mq` | 5.5.1 | delivery-gate Outbox |
| 向量检索 | `platform-vector` + 选定向量库 | 引入时写回 | rag-guard |
| 模型调用 | 本仓端口 + infrastructure 客户端 | PoC 选型后写回；不以 Spring AI 接管规则 | rag-guard |
| OCR/版面 | 独立计算服务 SPI | PoC 后写回 | parse |

提交配置时主机为 `127.0.0.1`，不写真实服务器地址和口令。

## 一次改动带齐三件事

1. 业务端口：入参和返回值只用本仓库强类型（禁止 Map）。  
2. 构建依赖、配置和客户端创建：只声明本次需要的构件。  
3. 封装实现：放在 `com.moonligh.report.infrastructure` 对应子包。

业务代码、领域规则和验收测试只调用业务端口；Redis / MQ / 向量 / DB / 模型客户端类型不越过 `infrastructure`。

失败转换成平台 `BusinessException` 或本仓可处理类型；不把失败响应解析成空业务对象冒充成功。

## 端口与封装位置（首次引入时创建）

| 工具 | 业务端口（示例） | 封装包 |
| --- | --- | --- |
| MySQL | 各聚合 `*Store` | `infrastructure.persistence`（`*Mapper` + XML） |
| Redis | 事件缓存 / 单飞锁端口 | `infrastructure.redis` |
| RocketMQ | `ArchivePublisher` / 通知投递端口 | `infrastructure.mq` |
| 向量库 | `KnowledgeRecall` | `infrastructure.vector` |
| 模型 | `InterpretationModel` | `infrastructure.ai` |
| OCR/版面抽取 | `DocumentExtractionPort`（Fake / Http） | `infrastructure.extraction` |

## 测试

验收与领域规则优先进程内 Fake，不强制连 Redis/MQ/真模型。  
封装类测试随工具提交，只验证端口与客户端这一层。默认 `mvn -B verify` 不依赖外网。
